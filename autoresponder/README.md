# autoresponder — автоответчик в Telegram

Юзербот на Telethon, порт `tg-autoresponder` для TeleScript. Пока режим включён, отвечает людям в личных чатах из папки (или во всех личных чатах, если `folder: null`) от имени владельца. Каждое входящее сообщение копируется в группу-ретранслятор, а ответ владельца на копию доставляется человеку.

## Команды

Пишет владелец, в «Избранном» или в чате из папки. Команды удаляются сразу после выполнения.

| Команда | Действие |
|---|---|
| `.start` | включить режим, начать новую сессию (приветствие, затем ответы модели) |
| `.start imit` | то же, но модель отвечает в стиле владельца и без приветствия; нужен `analyze-style` |
| `.stop` | выключить режим |
| `.reload` | сбросить счётчики лимитов (текстовые и голосовые) |
| `.ign` / `.noign` | в чате с человеком: исключить его из автоответчика / вернуть |
| `.mem текст` | записать заметку в чат памяти (работает и в группе-ретрансляторе) |
| `передай @user текст` | переформулировать текст и отправить пользователю (только «Избранное» и группа-ретранслятор) |

Если владелец сам пишет в чате, этот чат ставится на паузу до следующего `.start`.

Голосовые и видеосообщения не скачиваются и не распознаются. В ответ уходит готовая фраза (по умолчанию «опять гс»), модель не вызывается. Фразы лимитируются на чат, на всех и в сутки (половина текстовых лимитов), сверх лимита бот молчит.

Режим имитации честен: на прямой вопрос «ты бот?» модель не отрицает, что она ассистент; при сбое модели в этом режиме бот молчит, а не отвечает служебной фразой.

## Запуск

Точки входа: `autoresponder.main(["login"])`, `autoresponder.main(["run"])`; из командной строки то же самое:

```
python autoresponder.py login          # только вне TeleScript, вход по QR; в приложении не нужен, там берётся сессия TeleScript
python autoresponder.py run            # запуск бота, stdin не нужен
python autoresponder.py analyze-style  # собрать описание стиля владельца для .start imit
python autoresponder.py compact-style  # сократить сохранённое описание стиля
python autoresponder.py style-chats    # (для приложения) список чатов -> style_chats.json
python autoresponder.py style-draft    # (для приложения) черновик стиля по выбранным чатам -> style_draft.json
```

Без telethon запуск невозможен. В TeleScript отдельный вход не нужен: используется его сессия. Вне приложения вход только по QR, по номеру телефона его нет.

## Переменные окружения

| Переменная | Значение |
|---|---|
| `AUTORESPONDER_CONFIG_DIR` | каталог с `api.json`, `groups.json`, `profile.json`, необязательным `proxy.json` |
| `AUTORESPONDER_DATA_DIR` | `state.json`, `style.json`, `notes_compact.json`, песочница `empty/` |
| `AUTORESPONDER_SESSION` | путь сессии Telethon (без `.session`) |
| `AUTORESPONDER_API_ID`, `AUTORESPONDER_API_HASH` | данные приложения Telegram вместо `api.json` |
| `AUTORESPONDER_INSTANCE` | имя экземпляра, по умолчанию `autoresponder` |
| `ANTHROPIC_API_KEY` | ключ для запасного бэкенда через API |

Без переменных пути берутся из `~/.config/` и `~/.local/share/`.

## Файлы

Форматы совместимы с `tg-autoresponder`.

- `groups.json` — группа-ретранслятор (`relay_invite`) и чат памяти (`memory_invite`), ссылки-приглашения или id; оба поля есть в «Конфиге». Прямой ответ: ответ на копию сообщения в группе пересылок или в «Избранном» уходит собеседнику.
- `state.json` — `enabled`, `imitate`, `greeted`, `paused`, `ignored`, `relay_map`, `summaries`, `history`. Старый файл с ключом `war` читается, ключ игнорируется.
- `style.json` — результат `analyze-style`.
- `proxy.json` — необязательный прокси (его пишет приложение), без него соединение прямое.
- `profile.json` — переопределения, все ключи необязательны:
  - `name` (по умолчанию `v1pach`), `folder` (название папки Telegram, `null` — все личные чаты);
  - `history_fetch` — сколько последних сообщений читать из Telegram перед ответом (по умолчанию 30, `0` — только сохранённая история); в журнале `history: N messages`;
  - `chat_limit`, `global_limit`, `day_limit` — лимиты ответов модели;
  - `history_keep`, `history_roll_at`, `history_line`, `llm_input` — размер контекста и входа модели;
  - `voice_replies` — список готовых фраз для голосовых и видеосообщений (можно строку), по умолчанию `["опять гс"]`; выбирается случайная;
  - ключи LLM (новые): `backend` (`auto`, `cli`, `gemini`, `api` или список в порядке попыток), `model`, `style_model`, `gemini_model`, `backend_cooldown`, `api_key`, `api_url`, `llm_timeout`.

## Языковая модель

Цепочка бэкендов как в automod: claude CLI (через шим Termux) → gemini CLI → провайдеры из файла приложения → Anthropic API; недоступные пропускаются, бэкенд, упёршийся в лимит, отключается на `backend_cooldown` секунд. Всё в одном файле.


## Дополнительные провайдеры (GPT, DeepSeek, свои API, локальная модель)

Приложение кладёт JSON-файл и передаёт его путь в переменной `TELESCRIPT_LLM_PROVIDERS_FILE`. В файле лежат секреты, скрипт не пишет в журнал ни его содержимое, ни ключи, ни заголовки запросов (тексты ошибок очищаются от ключа и укорачиваются).

```json
{"providers": [{"id": "deepseek", "kind": "openai", "title": "DeepSeek",
                "base_url": "https://api.deepseek.com", "api_key": "...",
                "model": "deepseek-chat", "headers": {}, "timeout": 120}],
 "order": ["deepseek"]}
```

- `kind: "openai"`: любой OpenAI-совместимый API. `POST {base_url}/chat/completions`, заголовок `Authorization: Bearer <api_key>`, сообщения system + user, без стриминга, `temperature` 0.3. Необязательное поле `extra_body` добавляется в тело запроса, но ключи `tools`, `functions`, `tool_choice`, `function_call` из него вырезаются: инструменты модели не передаются никогда. Локальная модель на телефоне подключается так же: `base_url` вида `http://127.0.0.1:PORT/v1` (для неё прокси не используется). HTTP 429 и 402 и тексты про квоту или недостаток баланса считаются лимитом: провайдер пропускается `backend_cooldown` секунд. Остальные ошибки повторяются один раз. Запросы идут через urllib, системный прокси (`HTTPS_PROXY`) учитывается.
- `kind: "cli_codex"`: Codex CLI (вход через ChatGPT-аккаунт, бинарник `codex` в PATH или в `~/.local/bin`, на Android через шим). Команда: `codex exec --sandbox read-only --ephemeral --skip-git-repo-check -c approval_policy="never" [-m <model>] -`; промпт идёт в stdin, ответ берётся из stdout, запуск из пустой папки. Источники: [non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode.md), [CLI reference](https://developers.openai.com/codex/cli/reference).
- `order`: порядок использования; id, которых нет в `providers`, игнорируются, провайдеры вне `order` не используются (если `order` нет, берётся порядок файла).

`backend` понимает старые имена (`cli`, `gemini`, `api`), а также `codex` (Codex CLI с моделью по умолчанию), `providers` (все провайдеры файла по порядку) и любой `id` из файла; можно списком. `"auto"` = `claude`, `gemini` (если установлены), затем провайдеры файла в порядке `order`, затем Anthropic API (если задан ключ).

С моделью разговаривают посторонние, поэтому у неё никогда нет инструментов, MCP-серверов и источников настроек: claude запускается без инструментов и с пустыми настройками, gemini работает в пустой песочнице. Входящий текст считается недоверенным.

## Что убрано относительно tg-autoresponder

- `.war`, `.peace` и всё про двух ботов (теперь это обычные сообщения);
- распознавание голоса (whisper) и скачивание вложений;
- описание картинок моделью: картинка передаётся как `[картинка]`, а владелец получает сам файл в группе-ретрансляторе;
- вход по коду из SMS (нужен ввод с клавиатуры);
- привязка к xray, `proxy.json` стал необязательным;
- запуск нескольких экземпляров через `TG_INSTANCE` (заменено на `AUTORESPONDER_INSTANCE`).
